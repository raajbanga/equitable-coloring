Score of this answer

        
Sort the group sizes and add up the gaps between neighbors. The middle numbers cancel out, so the score is just the biggest group minus the smallest.

        

        
The best possible score is 0 when k divides n evenly and 1 otherwise. The program stops as soon as it reaches that score, because nothing can beat it.

      

    

    

      
Problem statement

      

        
Given a graph and a number of colors k, color every vertex so that:

        
    
          
  • no two vertices joined by an edge share a color,
    • 
          
  • all k colors are used, and
    • 
          
  • the color groups are as close in size as possible.
    • 
        

        
If no coloring follows the first two rules, the program prints “no such a sequence exists.”

      

    

    

      
Solver selection

      

        
    
          
  • k > n: some color would be empty, so there is no answer.
    • 
          
  • k = n: every vertex gets its own color.
    • 
          
  • n ≤ 16: dynamic programming (Dynamic programming tab).
    • 
          
  • n > 16: branch and bound (Backtracking tab).
    • 
        

        
Both solvers always find the best score. DP takes about the same time on every graph of a given size, but its memory doubles with every vertex, so it is only used up to 16 vertices.

      

    

    

      
Hardness

      

        
An answer exists exactly when the graph can be colored with k colors. For k = 3 that question is the 3-coloring problem, which is NP-complete.

        
No polynomial-time method is known, so the program has to search. The work goes into pruning that search: skipping branches that can't lead to a better answer.

      

    

    

      
Deterministic output

      

        
A graph often has several best colorings. The program always prints the same one:

        
    
          
  • Vertex 1 gets the earliest color it can, then vertex 2, and so on.
    • 
          
  • Colors are named in order of first use: Yellow, Blue, Red, Green, …
    • 
          
  • Lines are sorted by group size, then by name.
    •

Algorithm

      

        
Color one vertex at a time. If a vertex has no legal color left, undo the last choice and try the next one. Keep the best coloring found so far.

        
The color class bars show the state of the search:

        
    
          
  • Solid bar: vertices in the group right now.
    • 
          
  • Light bar: the most the group could still hold, counting every uncolored vertex with no neighbor in it.
    • 
          
  • From the light bars, the search works out the best score this branch could still reach. If that's no better than the best found so far, it skips the branch.
    • 
        

      

    

    

      
Pruning rules

      

        
Trying everything takes far too long, so four rules cut the search down:

        
    
          
  • Symmetry breaking. A vertex may only use a color already in use, or the next new one. Renaming colors gives the same groups, so those copies are skipped.
    • 
          
  • Forward checking. If an uncolored vertex already touches every group, the branch is dead.
    • 
          
  • Bounding. If the best score a branch could still reach is no better than the best found, skip it.
    • 
          
  • Ordering heuristics. Color vertices with the most neighbors first, and try the smallest group first.
    •

DP table

        

          

          

        

      

      

        
Algorithm

        

          
Instead of coloring one vertex at a time, build the coloring one whole color group at a time.

          
    
            
  • A legal group is a set of vertices with no edge inside it.
    • 
            
  • The table answers one question for every set of vertices: can it be split into j legal groups, each with a size between lo and hi?
    • 
            
  • Each answer comes from smaller sets. Take out one legal group that holds the set's first vertex. If the rest splits into j − 1 groups, the whole set splits into j.
    • 
            
  • The same smaller sets come up again and again, so each answer is saved and never worked out twice.
    • 
            
  • Once a size range works, walk back through the table to read out the groups.
    • 
          

          
The table has one entry per set of vertices (2ⁿ of them), so the program uses DP only up to 16 vertices.

DP runtime
Measured on random graphs with k = 3 (from the report).

      

        

        
Each extra 2 vertices make DP about 9 times slower (3² = 9), as the analysis predicts. At 20 vertices it already takes a second, which is why bigger graphs use branch and bound.

      

    

    

      
Complexity
n is the number of vertices. The input is an n × n grid, so the input size is N = n².

      

        

          
PartTimeMemory

          
            
Read, check, printO(n²)O(n²)

            
Dynamic programming (n ≤ 16)O(n² · 3ⁿ)O(2ⁿ)

            
Branch and bound (n > 16)O(kⁿ · k²)O(n)

          
        

        
    
          
  • Reading touches each of the n² entries once, so it is linear in the input size.
    • 
          
  • DP: each vertex is outside the set, in the group, or in the rest, so one pass costs about 3ⁿ. There are at most about n² size ranges.
    • 
          
  • Branch and bound: each vertex tries at most k colors, so up to kⁿ partial colorings.
    • 
          
  • Pruning makes real inputs fast, but the worst case stays exponential.
    •
